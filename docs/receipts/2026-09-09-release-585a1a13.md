## Limits

This receipt does not attest anything it did not measure.

- **No recovery proof was run.** The disposable backup-restore proof in the
  runbook exists to guard a schema migration. This release changes no schema —
  repository and production both remain at `053` — so that section was out of
  scope. A release that does move the schema must not reuse this precedent.
- **No canary pull request.** The end-to-end delivery canary was completed and
  closed on PR #124 during the 2026-09-08 rollout; it is a one-time proof and
  was not repeated.
- **The observer's GitHub token is unchanged and still expires 2026-12-05.**
  This window neither rotated nor re-verified it.
- **The predecessor release `b45ebd80` has no receipt.** It holds evidence only.
  That gap is named here rather than closed; this receipt covers `585a1a13`
  alone.
- **Nothing here proves the absence of another writer.** The eight-unit
  inventory is complete with respect to the runbook, not with respect to any
  ad hoc process that could reach the same database.
- **"Immutable release tree" is accurate about the application code and not
  about the interpreter.** Measured 2026-09-10, after this receipt was first
  written: `venv --copies` copies the interpreter binary, which the manifest
  hashes, but the venv ships no standard library at all — `venv/lib/python3.12/`
  contains only `site-packages`. `sys.base_prefix` stays at the uv-managed tree
  under `~/.local/share/uv/`, and 366 files totalling 8.19 MiB are loaded from
  there at run time by the three resident writers, `ssl.py` and `hashlib.py`
  among them. That tree is owned by the runtime uid, and so is this release
  tree. Three claims that circulated during that measurement were wrong and are
  corrected here rather than repeated: `os.py` is frozen into the hashed binary
  (`os.__spec__.origin == "frozen"`), `lib-dynload` contributes zero live
  bytes because uv links the extensions statically, and the certificate bundle
  resolves inside the release. As a security finding this is minor — no
  privilege boundary is crossed, and the runtime uid is already root-equivalent
  on this host through both the `docker` and `sudo` groups. As an attestation
  defect it is real: the manifest attests less than the sentence implies.
- **Six release trees now occupy 1.9 GB** under
  `~/.local/share/brain-v42/releases`. No retention policy has been decided; the
  filesystem stood at 81 % during this window.
