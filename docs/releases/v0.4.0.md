# brain_v42 v0.4.0 — release notes

No `CHANGELOG.md` exists in this repository; these notes are the changelog
entry for this release. They cover everything merged into `main` between
`v0.3.0` (2026-08-24) and this tag: 77 pull requests (#35–#112, with #38
absent from history — no merge commit for it exists anywhere in this repo),
368 commits total (`git rev-list --count v0.3.0..origin/main`).

## Database migrations (047 → 052)

Schema head moves from 046 to 052 — 046 (`brain_sessions` identity/nature
columns and the `closed_inactive` terminal state) already shipped in
`v0.3.0`. Every migration below is nullable / no-backfill unless stated
otherwise, per this project's decay doctrine.

- **047** — drops the closing XOR (`non-empty ledger XOR
  nothing_to_capture_reason`) from `brain_session_end`: the check had become
  hollow once the server itself could populate the ledger via derived
  capture, and would otherwise make some sessions unclosable.
- **048** — adds `brain_session_artifacts.attribution_mode`
  (`explicit` / `derived_deposit` / `derived_connection` / `derived_window`),
  with a partial index on the derived modes only, so a bad guess can be
  undone with a query instead of a scan.
- **049** — adds `dream_runs.closed_inactive_count` and
  `dream_runs.thinking_tokens`, and widens the `freshness_source` vocabulary
  with `plan_reindex` and `manual_update` on the six decay-tracked tables
  (migration corridor, PR #54).
- **050** — adds `project_focus_history`, an append-only audit trail for
  focus rewrites (`brain_set_project_context` previously overwrote
  `current_focus`, including to `NULL`, with no way to recover the prior
  text).
- **051** — adds `brain_session_checkpoints`, an append-only ledger of
  session judgment (state / blockers / next steps), enforced append-only by
  a `BEFORE UPDATE OR DELETE` trigger and `ON DELETE RESTRICT` on the
  session foreign key.
- **052** — adds a durable `access_log_daily` journal so human/machine
  access counters can be recomputed after `DecayFlusher` drains and deletes
  the transient `access_log` queue.

## Session lifecycle

- Derive capture into the connection's tracer from
  `BasePgRepository.create`, absorbing the tracer ledger on every explicit
  session command (PR #35).
- Bound the take-over path after filtering, and make the absorption journal
  say what it actually does (PR #39).
- Move the identity guard so it travels WITH the mutation instead of before
  it, absorbing before materializing so the receipt stops lagging a call
  (PR #40).
- Drop the capture-receipt XOR now that derived capture can fill the ledger
  server-side (047, PR #37).
- `open_session_count` speaks of humans only, never the tracer sessions
  derived capture introduced (PR #48).
- Pin the sweep's two closing paths (explicit `end` vs. the 7-day inactivity
  sweep) by nature, with no behaviour change (PR #105).
- Ship 050 (focus history) and 051 (session checkpoints) together with their
  writers and readers, held behind an operator apply window (PR #74).
- `brain_session_capture` / `brain_session_heartbeat` report *why* the
  ledger stayed empty, within the existing output-schema budget (PR #82).
- Every writer of the project focus is named and stamped, guarded by an AST
  scan (PR #86).

## Dream automation (pool, sweep, promote, events)

- Model-output project keys are censused and tested against an allowlist
  (PR #36).
- The night's primaries come back alive — end of the standing 410 errors
  against llama, with a weekly liveness probe in its own systemd unit, out
  of the night's own path (PR #42).
- The night reconciles its OK phases against the lines it actually wrote; a
  skip that writes its own line is no longer subtracted from the
  reconciliation gap, and REORG's entity-type alert fires once instead of
  eight nights running (PR #47).
- The briefing's margin line names which count it reports, and the date
  convention operates beyond the cap (PR #49).
- `apply`/`reject` for roadmap curations lands on the `brain-v42` side, and
  asymmetrically — the archive op is followed through to the INSERT
  (PR #52).
- `DRY_RUN` killswitches now fail closed, and the morning briefing reports
  the true state of both dry-run families instead of assuming they agree
  (PR #110).
- The nightly WET roadmap pass is limited to archiving and status changes
  only; the documentation guard now checks both directions (PR #71).
- The roadmap preflight refuses a WET night against an auto-apply primary
  project without an explicit operator acknowledgement (PR #85).
- The coverage fallback reports `UNMEASURED` instead of presenting an
  unmeasured run as clean (PR #95).
- The `promote` prompt no longer instructs a forbidden argument, and its
  largest input schema publishes its bounds from the model instead of prose
  (PR #97).
- The `promote` validator tolerates a dirty marker line and backfills
  `dream_run_id` before parsing (PR #106).
- A dream-events reader now reads night events across both the `codex` and
  `agy` rail dialects, with a census CLI (PR #107).
- The morning report gains structured REORG counts (read from the human
  access counter), shrunk ROADMAP batch counts, and orphan promotion counts
  (PR #100, #103, #109).
- The `DEGRADED` reader learns `extract`'s current output shape (PR #88).
- A night served by the standby model no longer prints a false "no
  failures" (PR #73).
- `dream_runs.thinking_tokens` is asserted never `NULL` on a row that
  carries a model (PR #104).

## Search

- `group_by_type` now honours the caller's requested `types`, and
  `brain_search` journals the parameters it actually received (telemetry)
  (PR #111).
- An empty `brain_search` result now explains itself instead of returning
  bare zero results, and an empty shard no longer degrades the whole query
  (PR #112).

## Other fixes and hardening

- HNSW index churn is measured against real embeddings rather than
  synthetic vectors (PR #41).
- Alembic upgrade steps derive from the migration graph instead of a
  linearized order; the `create_all()`↔chain parity check now covers all 18
  previously-missing `CHECK` constraints (PR #44).
- Metrics counters are kept per rejection code across the three receivers,
  `close()` is finally wired, and a non-loopback bind posture becomes a
  named choice with the default unchanged (PR #45).
- Machine-attributed rails that were silently counted as human provenance
  stop being counted that way, with the SQL mirror kept in sync (PR #50).
- MCP surface hygiene: the dream-only tool trio refuses by name and the ADR
  alias states itself; unarchiving a learning no longer touches the GPU,
  closing a measured asymmetry (PR #51).
- The gateway preflight proof covers all four contract clauses instead of
  just one (PR #53).
- `roadmap --apply-ids` is bound to a declared project, with a bounded
  description shown to the curator (PR #63).
- The integration suite now reports out loud when every test was skipped;
  the plan-index repairer reviews migrations 047–049 and guards their
  contiguity (PR #65).
- A human unarchive action stamps `freshness_source=manual_update`; the
  codex dream rail keeps its reasoning-token count instead of dropping it
  (PR #67).
- Dated tickets in the briefing sort by nearest deadline first (PR #69).
- The MCP process can present a file-sourced bearer to the embedding shim,
  closed by default and fail-closed when configured (PR #70).
- The integration test banner fires on "nothing was measured", not merely
  on a missing environment variable (PR #72).
- The network-boundary documentation names the metrics validator and adds a
  local probe that replays its claims (PR #89).
- The integration database is prepared only for tests that request it, not
  for every file under `tests/integration`; the boundary probe requires the
  dream capability flag read from the same `EnvironmentFile` used by both
  systemd units (PR #91, #92).
- The codex-gateway `/ready` contract is proven without root privileges
  (PR #93).
- The three loopback notions in use across the codebase are characterized
  and their disagreement confined to `127.0.0.0/8` (PR #99).
- ADR promotion gets its own dedicated tool; the `brain_list_adrs` alias is
  dropped (PR #102).
- An unregistered `related_to` graph endpoint now degrades to a warning
  instead of failing `brain_learn` after the underlying commit has already
  succeeded (PR #108).
- Batch of smaller fixes: dream provenance, activity registry, `brain_list`
  scope, a Postgres version pin, an HNSW benchmark, and additional DR
  receipts (PR #87).
- The schema-residue guard now closes its whole class of defect instead of
  the single DDL family it originally witnessed (PR #76).

## Versioning

- `pyproject.toml` and `README.md#versioning` move from `0.3.0` to `0.4.0`.
- The package version reported by `/health` and by
  `brain_v42.release.package_version()` remains derived from the installed
  distribution metadata at runtime — no source file hardcodes the version
  string other than `pyproject.toml` and the `README.md` prose that mirrors
  it.
- No lossless downgrade is promised at any version; migrations 037 and 039
  still refuse their own `downgrade` under the conditions documented in
  `README.md#versioning`.
